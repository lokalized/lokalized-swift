# Manifest parsing and validation

M7A exposes synchronous, I/O-free `LocalizedStringLoader.parseStringsManifest` overloads for `Data` and `String`, and `validateStringsManifest` overloads for `StringsManifestValue` and `StringsManifestV1`. The contract is pinned to JS commit `617670da887b0c684e2589882447b6b93297f2f7`; Java has no manifest counterpart. A `StringsManifestV1` initializer creates an immutable claim, not a verified load. Every validation and planning door checks that claim again.

The wire shape remains format version 1 with `catalogVersion`, `catalogFingerprint`, seven build-identity fields, `fallbackLocale`, `baseUrl`, `files`, and `tiebreakerLocalesByLanguageCode`. Each file carries a nonempty `url`, lowercase 64-digit `sha256`, and optional `decodedBytes`. Unknown manifest and file members are tolerated and omitted from the returned value. Reviewed predecessor JS source used `tiebreakers`; that spelling is not a synonym in this pinned shape.

`StringsManifestValue` is the explicit decoded-input carrier. It can represent nulls, incorrect field types and missing members without `[String: Any]` or external JSON dependencies. Object members retain exact UTF-16 names and order. Semantic validation applies JavaScript object behavior: later equal names replace earlier values without moving their first position; integer property names in `0...4294967294` precede ordinary members in numeric order. Raw-source duplicates are rejected instead. Typed `StringsManifestV1` maps have no declaration order, so their decoded projection uses deterministic UTF-16 key order. Swift string canonical equivalence must not collapse distinct raw names; map/member keys use `ExactString`.

Validation proceeds in these phases, preserving the first refusal:

1. Require an object, numeric format version 1, nonempty catalog version and correctly shaped catalog fingerprint.
2. Validate CLDR version and data fingerprint shapes, then their compatibility with this build. Require `localeDataMode: "pinned"`, `cardinalityMode: "exact"`, version-shaped behavioral vectors, a nonempty IANA identity string and full lowercase IANA fingerprint, then check all three against this build. No missing wire identity field receives a default.
3. Validate the fallback tag against the pinned locale data and JDK syntax/rebuildability rules. Preserve JDK projection without collapsing distinct CLDR aliases.
4. Require an absolute base URL and one of `http:`, `https:` or `file:`. Require a files object and enforce the file-count limit before entry work.
5. In decoded member order, validate and normalize each file key, reject an equal normalized key, require its entry object and nonempty URL, validate the resolved URL and scheme, require its digest, then validate optional decoded size.
6. Validate tiebreaker keys and each ordered candidate, then validate complete orders against the **full declared manifest**. Every multi-catalog primary language needs an explicit exact permutation. Extra language groups, repeats, missing siblings and unrelated entries fail. Undetermined and private-use catalogs have no broad-language group. Singleton orders are not synthesized into identity. Normalized tiebreaker-key collisions retain the later declaration, matching this JS snapshot.
7. Elect the fallback: an exact normalized file tag wins, otherwise a sole CLDR equivalent wins, otherwise the authored tiebreaker order selects an equivalent. Shared primary language alone is insufficient. Zero equivalents fail with the known locale list. Ambiguous undetermined fallbacks must name one declared tag exactly.
8. Recompute the full catalog fingerprint from its canonical projection and reject disagreement.

Validated output contains normalized file/tiebreaker keys and the elected authored fallback. It retains the original `baseUrl` and per-file `url` spelling. URL validation uses the shared manifest resolver; planning records its absolute serialized result. Foundation URL behavior is not silently substituted for WHATWG resolution. Common validation permits all three schemes; future transport doors narrow them before I/O.

Validation is a single pass, and a returned claim is revalidated at every subsequent public door. The pinned JS normalization is not idempotent for every JDK carrier: `UND-x-foo` becomes `und-x-foo` on first validation, then `x-foo` on revalidation. Identity projection also normalizes its fallback again, while retaining the file and explicit tiebreaker keys supplied to that projection. A once-accepted claim can therefore fail its fingerprint check at a later door. M7A preserves this measured shared behavior; it does not silently revise the wire standard.

Unicode and punycode special-host processing remain an unfinished native URL capability. Such inputs retain `ManifestURL.Failure` with `.unsupportedFeature` as the configuration refusal's cause, through both raw parsing and decoded validation. Ordinary invalid URLs retain the pinned refusal without a cause. The independent URL audit selects pending host-processing rows from their inputs and reports that capability separately; acceptance parity for these URLs is not claimed.

Manifest schema numbers intentionally use binary64 projection, separately from Lokalized's exact decimal expression/plural carriers. `decodedBytes` must be finite, integer-valued, nonnegative and at most `9007199254740991`. Thus raw `1.00000000000000000001` projects to accepted format version 1, and `9007199254740990.9` projects to accepted decoded size `9007199254740991`, as in JS. The optional size describes delivered body octets after HTTP content decoding and before UTF-8/BOM processing. M7A does not read or verify those bodies.

The raw parser bounds bytes before UTF-8 decoding and counts UTF-16 characters before stripping exactly one leading BOM. **Manifest `Data` also incurs the reader-character limit**, unlike catalog `Data`. It rejects blank input, checks nesting before JSON syntax, then uses the strict ordered reader without stripping another BOM. Whole-source syntax errors precede duplicate inspection; repeated root members precede the first nested repeat. Nested-repeat paths are capped at 4,096 UTF-16 units in the message. Manifest duplicate errors intentionally have no structured `path`, matching the pinned JS boundary. Data/text parsing does not charge aggregate bytes, translation nodes, warnings or discovery; only file count participates in semantic manifest validation. Decoded-object validation does not invent source byte, character or JSON-depth charges.

Schema, compatibility and fingerprint failures use native `ConfigurationError` with `.invalidArgument`. JSON syntax and duplicate failures use `StringsParseError`; syntax retains one-based line/column and the native `JSONReadError` cause. The manifest wrapper reconstructs syntax locations from UTF-16 offsets using the pinned reader's CR/LF line breaks with CRLF counted once, in both the outer error and its cause. For an unsupported string escape, it also moves the shared reader's consumed cursor back to the offending code unit. These adaptations preserve the manifest cursor without changing catalog-reader behavior. For raw byte/character/UTF-8/blank/depth failures, Swift consistently uses `StringsParseError`, while this JS snapshot leaks generic `Error` before its syntax wrapper. That is an explicit native phase adaptation, not a claim of identical exception classes. Received-value diagnostic numbers use Swift's shortest digits normalized to ECMAScript decimal/scientific thresholds; the frozen JS vectors qualify those observed messages, not every malformed binary64 rendering. The JCS fingerprint itself contains only the fixed numeric format version 1 and does not depend on that general diagnostic formatter.

`ConformanceRunner.manifestValidationSelfTest()` provides 118 independent native checks. XCTest adds raw-source duplicate precedence, exact Unicode names, BOM/UTF-8 behavior, both manifest input budgets, syntax locations, bounded diagnostic paths, numeric projection and declaration-order differences. Frozen JS contract vectors provide separate differential evidence. None of these checks adds invented donor-corpus passes.

M7A performs no catalog I/O and returns no `LoadedStrings` or verified-load record. Streaming reads, digest-before-parse body verification, partial load policy, cancellation ownership, transport/request options, loaded-record revalidation, publication and runtime replacement remain later M7 work. Manifest digests establish consistency with the supplied manifest; they do not authenticate that manifest. The implementation adds no external package dependencies; hashing uses Apple's system CryptoKit framework.

A measured diagnostic-output boundary remains outside the 499-case archive: truncating a valid supplementary character at the 4,096-unit path cap can leave a lone high surrogate in JS's error message. Swift's `String(decoding:as: UTF16.self)` replaces that truncated unit with U+FFFD. For an object key of 4,092 ASCII `a` characters followed by `😀x` and a nested duplicate, both paths have 4,096 units; their final units differ (`D83D,2026` versus `FFFD,2026`). Input text is valid and retained; this concerns the bounded error-message carrier only. Local evidence is `.build/reports/m7a-diagnostic-unicode-gap.json`. It is an explicit release representation qualification gap, not an added frozen-corpus pass or a ratified mapping.

# Pinned plural rules and qualification

M2 implements cardinal, ordinal and cardinal-range classification with CLDR 48.2 data and exact decimal operands. The library evaluates compiled tables; it does not read `Reference` files, decode JSON, download data or consult the platform's ICU plural rules. The package has zero external dependencies. The development generator needs Python's standard library; the standalone audit uses the platform's Foundation and CryptoKit.

## Provenance and regeneration

The input is the frozen [plural export](../Reference/cldr-plural-data.json), with SHA-256 `7ade4692762aac80144f915b62de19f29eb039ec3cf28c3f9f2c34b810cdc0e7`. The complete pinned CLDR data fingerprint is `9b4f24165b6dd1ee6dbb5f0822abc7bcde49c5b94d35903045826b45e1f30e68`; it identifies the shared CLDR baseline rather than this individual file. The source retains the [Unicode data license](../Reference/THIRD-PARTY-NOTICES.spec.md).

```sh
python3 Tools/generate_plural_data.py --check
python3 Tools/generate_plural_data.py --refresh
```

`--check` regenerates in memory and compares the complete generated Swift file. `--refresh` is an explicit local rewrite; both reject changed input bytes, versions, unsupported relation syntax, duplicate locale/category/range rows and invalid sample representations. They require neither sibling repositories nor network access. Repeated refreshes produce identical bytes.

[PluralTables.swift](../Sources/Lokalized/Data/PluralTables.swift) carries the source hash, CLDR version, shared data fingerprint, generator version `1.0.0` and compiled payload SHA-256 `2cfa9f0bab871bdee6df32caab91596e6ad29d7a85b259c1301f85c3add19d0d`. The payload hash covers canonical compact JSON of the generated bytecode, group descriptors and range tables; it excludes the generated Swift formatting.

## Actual representation

| Component | Checked-in representation |
|---|---|
| Cardinal rules | 40 shared groups, 224 direct locale tags |
| Ordinal rules | 25 shared groups, 108 direct locale tags |
| Conditions | 96 interned programs; 1,661 `UInt32` words, 6,644 bytes of word payload |
| Cardinal ranges | 22 shared groups, 91 direct locale tags; 36 `UInt8` cells per group, 792 bytes of cell payload |
| Examples | Space-delimited literal strings with separate finite/infinite flags, preserving decimal scale and sample order |
| Generated Swift source | 55,261 bytes; this is source size, not linked binary or heap size |

Conditions use `dnf-u32-v1`: an OR-clause count, then each AND-clause's relation count, followed by operand index, modulus, negation flag, interval count and interval endpoint pairs. A zero OR count means an unconditional rule. Operand indices are `n,i,v,w,f,t,c,e`; all pinned endpoint/modulus constants are nonnegative integers at most 1,000,000. Interval membership requires an integer-valued operand; a singleton compares numerically, so `1.00 = 1` matches while `0.5 = 0..1` does not. Negation applies after membership, and AND binds more tightly than OR.

Runtime group descriptors are immutable Swift arrays. Locale indexes are dictionaries constructed from the fixed space-delimited tag groups on first use; examples split their literal sequences when requested. This is the actual M2 schema, replacing the earlier M0 blob experiment. Initialization allocation, lookup performance and linked binary size have not yet been measured. The payload sizes above do not claim to measure those costs.

## Public behavior

`Cardinality.forNumber` and `Ordinality.forNumber` accept `NumericValue`, native integers, `Float`, `Double` or `ExactDecimal`, with optional visible decimal places and numeric limits. `forOperands` accepts an already validated `PluralOperands`, including a compact exponent. Decimal input retains visible trailing zeros; native integers and binary floats follow the numeric core's Java-compatible normalization. Classification uses absolute expanded operands, while `sourceNumber` retains the signed unexpanded value for later expression/interpolation work.

`Cardinality.forRange(start,end,locale:)` checks cardinal support first. An explicit CLDR row selects its stated result; an absent pair or absent range group takes the end cardinality. Ordinals use their own rule groups. A locale with cardinal support and no explicit ordinal group uses the `und` ordinal group (`OTHER`), while an unsupported locale throws `UnsupportedLocaleError` for either classifier. Support queries return an empty array for an unsupported, well-formed locale; they preserve enum order for supported categories. The direct-tag inventories are lexical arrays; the ordinal inventory includes the cardinal tags because every cardinal-supported locale supports ordinal fallback. `und` is the public spelling of the root group.

The Java example methods retain their shared names: cardinal integer/decimal examples and ordinal integer examples return category dictionaries containing `Range<Int>` or `Range<ExactDecimal>`. Iterate `Cardinality.allCases`/`Ordinality.allCases` when dictionary output needs category order. `Range<Value>` is an immutable sequence of representative values plus `isInfinite`; the flag indicates that the pattern repeats beyond the stored samples. It is distinct from Swift's interval type, so qualify `Lokalized.Range` where both names are in scope. Conditional equality, hashing and `Sendable` follow the element type.

## Independent audit

```sh
swift run LokalizedConformance --plural-data --reference Reference
```

The development audit verifies the independent [expanded vectors](../Reference/cldr-conformance-vectors.json) against SHA-256 `404e2fb3fbff0ee9564226527c0645c723a16afaf76dff2db7942e5015a54926`, and verifies the source export's separate digest before examining example helpers. It takes expected categories directly from authored samples and explicit range rows; it does not interpret production rules into expected outcomes.

Qualification compares 12,396 cardinal samples, 2,645 ordinal samples, all 8,064 category-pair cells across the 224 direct cardinal tags, 450 support/inventory checks, and complete example maps (796 integer ranges and 440 decimal ranges). Integer examples include the 116 cardinal-supported locales that inherit ordinal root examples. The report contains 24,227 checks; any mismatch fails, and fixed traversal totals reject an incomplete pass. The first 64 mismatch details are retained with a full failed-check count. Input digest/version/provenance failures throw before qualification. XCTest invokes this same audit and verifies its exact inventory; additional native tests cover decimal scale, huge modulo, compact exponents, support asymmetry, range defaults, scripts/regions, limits and mutated reference refusal.

## Locale integration in M3

Plural classification now uses the complete pinned JDK tag kernel and CLDR canonicalization before walking `language-Script-REGION`, `language-Script`, `language-REGION`, `language`. It keeps Portuguese `pt-PT` cardinal rules distinct from `pt` while ordinal/range lookup can inherit `pt`. `und`, `und-Latn` and private-use-only tags use root plural rules. Invalid full syntax or nonrebuildable Java locale fields raise the native `PluralLocaleError`.

The exhaustive range audit derives direct language aliases from the separately hashed raw CLDR locale export. This includes `mo` inheriting Romanian range rows; direct plural inventory membership does not bypass canonicalization. The corpus adapter preserves the oracle's lenient `Locale.forLanguageTag` ingress separately from the strict Swift String API. [Locale data](LOCALE-DATA.md) and [matching](LOCALE-MATCHING.md) document independent qualification of those services.

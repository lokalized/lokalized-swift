# Declaration-preserving fixture inputs

`behavioral-vectors.json` canonically sorts object members. That preserves the
semantic catalog tree but loses declaration order, which is observable in loader
warning order and diagnostic precedence. Recreating fixture files from those
sorted objects cannot replay every recorded input faithfully.

`Reference/materialized-fixtures.json` archives the authored input files from
the already reviewed specification commit
`2d9547700d88ad8b7bc73e4d2c0fe18bdffb68a4`, preserving their actual
materialized bytes. It contains **586 fixtures and 2,187 ordinary file records**,
including empty file maps, structured files, raw-text/byte overrides and child
files declared by directory-shaped entries. It contains no recorded expected
observations and does not execute a Java oracle.

The 1,982,751-byte archive SHA-256 is
`8203dbeae22b862f7514c3fec2786a42782067f1f532b96aab9314b1d5aea146`.
Its corpus SHA-256 remains the frozen
`1eb74caf8524c0a3b33dca99addb268c86b64eb8321fac03257474ddaa3c9753`.
The runner must reject a missing/unknown fixture or file record; falling back to
canonical reserialization would reintroduce the lost-order defect.

Each `fixtures[fixtureID].files[tag]` record has `bytesBase64`, `byteCount` and
`sha256`. `source.authoredSources` preserves each original fixture JSON file's
bytes/path/hash. `source.recipe` preserves the pinned
`tools/vector-oracle/build.mjs` source. The authored-source index SHA-256 is
`8a6ca78f18349bc436bcee0f04bc994cd0f406a194900fe7f24c1848adeba324`;
recipe SHA-256 is
`e4f0b207b32fb0c950943f09a0b8b695a98fd5cfef0728e72ac5919dea3479db`.
This additional input archive is separate from the frozen 21-artifact M0 baseline.

```sh
python3 Tools/materialize_fixtures.py --check
```

Ordinary checking uses Python's standard library and the two local archives
only. It independently verifies the whole archive, every authored source, recipe
and materialized file pin, reproduces all generated bytes, rejects unknown/missing
members, and compares all authored fixture semantic trees to the frozen corpus.
Object order is deliberately ignored in that semantic check; array order, exact
UTF-16 string/key identity, booleans/null and JavaScript binary64 numeric values
are retained. Structured files are independently decoded and compared to their
corpus trees. Raw invalid JSON/UTF-8 inputs are compared as bytes.

```sh
python3 Tools/materialize_fixtures.py --refresh \
  --source-root /path/to/workspace --node /path/to/node
```

Refresh reads every source with `git show` at the explicit pinned commit, never
from a dirty working tree. Structured files use the oracle recipe
`JSON.stringify(contents, null, 2) + '\n'`; raw text overrides come next, then
raw Base64 bytes. Python's serializer implements this pinned input profile,
including ECMAScript array-index member ordering, number formatting and lone
surrogate handling. Refresh verifies **every file byte** against actual local
Node `JSON.stringify` before writing. Initial verification used Node 26.5.0.
The checker does not pretend to be a general ECMAScript implementation.

Independent verification confirmed `Zulu` precedes `Alpha`, and `zeta` precedes
`beta`, in the warning-order fixture's materialized bytes. An isolated copy of
the checker and archives passed with `PATH` empty, and an omitted fixture failed
the independent whole-file pin. Refresh refuses to replace the archive with
different bytes unless the pins are deliberately revised.

Filesystem shapes remain transport metadata in the corpus/authored inputs:
this archive does not create missing paths, regular-file roots, directories or
FIFOs. Future filesystem adapters must honor those shapes instead of treating
every archived byte record as an existing ordinary file. The archive only
recovers inputs; it neither changes the shared contract nor makes parity claims.
